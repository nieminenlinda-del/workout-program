# Linda Lift

Mobile-first PWA for gym-phone session logging. Phase 1 is **today’s workout only**: readiness, static A–D templates, per-set weight/reps/RPE, rest timer, save to IndexedDB.

Phase 2 (auto-progression toward a **2026-11-21** test, including PowerCombo `hypertrophy` / `strength_peak` mode) is typed and documented in [ARCHITECTURE.md](./ARCHITECTURE.md) — the engines are not implemented.

## Quick start

```bash
npm install
npm run dev
```

Open the printed local URL on your phone (same Wi-Fi) or in a mobile viewport. `npm run dev` binds `--host` so other devices on the network can reach it.

| Script | What it does |
| --- | --- |
| `npm run dev` | Vite dev server |
| `npm test` | Vitest (schema, templates, repository) |
| `npm run build` | Typecheck + production PWA build (service worker) |
| `npm run preview` | Serve the production build |

### Install as an app (phone)

1. `npm run build && npm run preview` (or deploy `dist/`).
2. Chrome/Edge: menu → **Install app** / **Add to Home Screen**.
3. iOS Safari: Share → **Add to Home Screen**.

The web app manifest and service worker are generated by `vite-plugin-pwa`. Logging works offline after the first load; data never leaves the device.

## Phase 1 flow

1. **Today** — default **Monday / Day A** squat template. Pick A–D (Mon/Tue/Thu/Fri).
2. **Readiness** — sleep, soreness, energy, pain, motivation (1–10). Auto light `GREEN|YELLOW|RED` (override allowed). Pain flag.
3. **Workout** — seed lifts, swap listed alternatives, log each set (`weight_kg`, `reps`, `rpe`, `completed`, optional `amrap`).
4. **Rest timer** — starts after a completed set using that set’s `rest_sec` (T1 longer, accessory/core shorter). Pause/resume, +15s / +30s, or skip to log the next set. Recovers from lock/background via wall-clock; buzzes + beeps when time is up (vibration does not need audio).
5. **Interval timer** — separate screen from Today for circuits (rounds × work / rest). Same cues at phase changes.
6. **Save** — notes, persist `SessionLog` in IndexedDB behind a repository interface.

## SessionLog (persisted)

```ts
{
  session_id, date, template_day, // A–D (Mon=A, Tue=B, Thu=C, Fri=D)
  readiness: { sleep, soreness, energy, pain, motivation, light },
  lifts: [{ name, style?, exercise_id, sets: [{ weight_kg, reps, rpe, completed, amrap? }] }],
  pain_flag, notes
}
```

Drafts are stored separately so a mid-session refresh on the gym floor does not lose the log.

## Seed templates (static)

Working weights are placeholders, not a TM calculator. Documented TMs: squat **67.5** / bench **50** / deadlift **85** kg.

| Day | Focus |
| --- | --- |
| Mon A | `squat_low_bar` T1, `rdl`, `reverse_lunge` or `goblet_squat`, `plank` or `dead_bug` |
| Tue B | `bench_regular` T1, `row_barbell` or `row_db`, `overhead_press`, `band_pull_apart` |
| Thu C | `deadlift_conventional` T1, `glute_bridge` or `hip_thrust`, light `rdl`, `side_plank` |
| Fri D | `bench_regular_volume`, `front_squat_light` or `goblet_squat`, `pull_up` or `pull_up_band`, optional `curl_db` / `tricep_pushdown_band` |

Primaries are low-bar squat, regular bench, conventional deadlift only — no sumo / high-bar / close-grip as programmed T1s.

## Out of scope (Phase 1)

Auth, social, diet, live auto-progression, full TM calculator, wave prescription UI beyond these four seed days.
